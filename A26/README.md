# 第 26 篇：射频测试与频偏校准，过认证前要会的几件事

基线：tc_ble_simple_sdk V3.4.2.2 + patch_0001。

EMI 测试用 BQB_EMI_Demo 默认配置。这里是读写频偏校准值的自测固件，第 27 篇的 Flash 写保护自测也在里面。

| 目录 | 编译配置 | 改了什么 |
|---|---|---|
| [b80_ble_sample_a26](b80_ble_sample_a26/) | `b80_ble_sample` | 在第 18 篇带日志的 ble_sample 上加开机自测：打印校准扇区 0x7E000 的情况和模拟寄存器 0x8a 的前后值；**0x7E000 整个扇区为空时会写入测试值 0x15**（下次开机生效），只剩这个测试值时再擦掉；另外在被锁住的低 256 KB 里的 0x3F000 先带锁写、再解锁写，读回对比后擦除并恢复锁。**它会写 Flash 校准扇区，只在开发板上跑，别烧到产品上。** |

## 每个目录里有什么

- 改过的源文件，按 SDK 根目录下的相对路径摆放（Platform 是 `tc_platform_sdk-V3.5.1/`，BLE 是 `b80_ble_sdk/`）；
- `改动.diff`：相对官方 SDK 的差异（BLE 是打完 patch_0001 之后）；
- `<目录名>.bin`：我按这些文件编出来的固件，BDT 从 Flash 地址 0 下载。

| 目录 | 替换文件 | bin 字节 |
|---|---|---|
| b80_ble_sample_a26 | `drivers/printf.h`<br>`vendor/ble_sample/app.c` | 48212 |

sha256 见 `改动清单.json`。

## 怎么用

1. 准备一份干净的 SDK（见仓库根目录 README），先备份要被覆盖的文件。
2. 把某个目录里除 `改动.diff` 和 `.bin` 以外的文件，按原路径覆盖到 SDK 根目录；或者在 SDK 根目录执行 `git apply <目录>/改动.diff`（SDK 用 git 管着的话）。
3. IoT Studio 导入 `project/tlsr_tc32/B80`，选表里的编译配置编译。
4. 换下一个目录之前，先把上一个目录改过的文件恢复成原样。

每个固件测到哪一步（只编译、上板看现象还是仪器实测），以文章开头的「验证状态」为准。
